Evidence, not verdicts

It writes down what happened. Deciding why stays with you.

  1. OBSERVED

    Every record says how it is known

    Observed from the API, derived by a documented rule, or unknown. Nothing is dressed up as more certain than it is.

  2. Gaps are drawn, not hidden

    When it wasn’t watching — a restart, a missing permission — that time is hatched. A quiet stretch is never mistaken for a calm one.

  3. connection, not cause

    It links, it never blames

    It shows what changed before a failure — on the workload, its config, its node — and leaves the conclusion to you or your agent.

01 · Overview

Your day as a timetable.

Every CronJob run on one line, failures in red, what’s still due outlined. A five-day strip to scroll through time, the exceptions that need a look, and planned maintenance as a band — not as an alarm.

  • Missed runs and runs that ran long, grouped
  • Run time against its own baseline: “+34% longer”
  • Your time zone or UTC, in English or Turkish

02 · Explorer

Every record, one search away.

Filter like you would in your log tool — namespace:shop severity:warning — then open a failure and see what was recorded in the hour before it.

Recorded before this

  • 7 min · Deployment spec written by kubectl-edit
  • 12 min · ConfigMap it references changed, by argocd-controller

What it keeps for you

  • Who changed it

    Every spec write with the client that made it — argocd, helm, kubectl — from Kubernetes’ own field managers.

  • Config changes, no values

    ConfigMap writes and the keys that changed, never their values. Secrets: metadata only, and only if you turn it on.

  • Releases and revisions

    Each rollout with its Pods, what changed in the template, and a fixed rule’s findings — not a health score.

  • Any moment, again

    Which image ran where last Tuesday at 10:00 — and whether OpsTide was watching then.

  • Scheduled jobs, kept honest

    Missed starts, runs that never confirmed, and run time against a 23-day baseline.

  • Planned work, labelled

    Maintenance windows from your Helm values mark what happened inside them. Nothing is muted.

Security

Built to be allowed in production.

Read the full RBAC before you install. It is short.

Verbs
list · watch
Never asked for
exec, logs, Secret data, any write
Secrets
Off by default. When on: metadata-only requests, with the last-applied annotation and managedFields dropped on arrival. The grant itself is list & watch on secrets.
Scope
Whole cluster, or only the namespaces you list
Access
Token for the UI and API; nothing is sent anywhere

Running in two minutes

Try it first · no cluster, no Docker

# sample data, opens on 127.0.0.1:8080
git clone https://github.com/mihnk/opstide
cd opstide && make demo-local

Needs Go 1.26, and Node 22 to build the UI.

Install in your cluster

helm install opstide oci://ghcr.io/mihnk/charts/opstide \
  -n opstide --create-namespace
kubectl -n opstide port-forward svc/opstide 8080:80
# then open http://127.0.0.1:8080

Sign in with the token from the opstide-auth Secret; every chart value is in the install guide. OpsTide is in early development (v0.1): the chart is published with the first release.
